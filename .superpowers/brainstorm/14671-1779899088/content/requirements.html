交互需求全景

按三个维度分类：展示方式、交互类型、通信模式

📊 展示方式 presentation

  • Markdown — 现有，保留
  • 表格 — 结构化数据
  • Diff — 代码变更对比
  • 流程图 — 节点+边
  • 线框图 — UI mockup
  • 图表 — 柱状/折线/饼图
  • 文件树 — 目录结构
  • 对比视图 — 左右对比方案
  • 时间线 — 甘特图/阶段
  • 卡片 — 搜索结果展示

🖱️ 交互类型 interaction

  • 单选 — 从 N 个中选 1
  • 多选 — 从 N 个中选 M
  • 表单 — 输入框/下拉/复选框
  • 确认/取消 — 简单 yes/no
  • 自由文本输入 — 用户打字
  • 点击展开/钻取 — 逐层深入
  • 拖拽排序 — 重新排列
  • 内联编辑 — 直接修改内容
  • 审批 — approve/reject/modify
  • 文件选择 — 浏览并选择文件

🔄 通信模式 pattern

  • Q&A 单轮 — "写段代码"，Agent 返回代码 (已有)
  • 多轮对话 — Agent 提问→用户回答→Agent 继续
  • 提议→审批→执行 — Agent 展示方案，用户审批后执行 (HITL)
  • 实时流式 — Agent 边思考边输出
  • 多方案对比选择 — Agent 出 A/B/C 方案，用户选最优
  • 分步向导 — 多步骤配置，每步一交互
  • 后台通知 — Agent 完成任务后通知用户查看
  • 协作编辑 — Agent 和用户同文档协作

关键问题

这些需求可以抽象为一个通用模式：

Agent 产出结构化 View[] + 可选的 pending interaction
     → EventBus 广播到所有 UI 通道
     → 各通道独立渲染 + 收集交互
     → 交互结果回调到 Agent
     → Agent 恢复执行
