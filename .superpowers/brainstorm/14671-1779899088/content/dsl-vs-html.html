实际测试题：让 LLM 生成"三方案对比 + 投票"组件

DSL 输出

{
  "type": "page",
  "children": [{
    "type": "row",
    "children": [
      {"type": "card", "title": "方案 A", "features": ["独立部署"], "action": "vote:a"},
      {"type": "card", "title": "方案 B", "features": ["简单运维"], "action": "vote:b"},
      {"type": "card", "title": "方案 C", "features": ["混合架构"], "action": "vote:c"}
    ]
  }]
}

评估：结构简单，LLM 按 prompt 给的 schema 填充即可。成功率>90%。

DSL 进阶测试：复杂嵌套

{
  "type": "page",
  "children": [{
    "type": "tabs",
    "tabs": [
      {"label": "概览", "content": {"type": "table", ...}},
      {"label": "详细", "content": {
        "type": "grid",
        "columns": 2,
        "children": [
          {"type": "chart", ...},
          {"type": "card_list", ...}
        ]
      }}
    ]
  }]
}

评估：嵌套层次超过 5 层时，LLM 容易漏字段或结构不对。成功率~60%。
对策：prompt 中给具体示例 + Zod schema 校验失败自动重试。

HTML 对比

<div style="display:flex;gap:16px">
  <div class="card" onclick="select('a')">
    <h3>方案 A</h3>
    <ul><li>独立部署</li></ul>
  </div>
  ...
</div>

评估：LLM 生成 HTML 非常自然。布局、样式、嵌套全在训练数据中。错误主要是标签不闭合或 onclick 拼写错。成功率~95%。

核心权衡

选 HTML：质量优先

  • LLM 产出质量高（95% 成功率）
  • 布局丰富、样式灵活
  • 安全靠外部消毒（DOMPurify）
  • 适合：重视展示效果

选 DSL：安全优先

  • LLM 产出需 prompt 工程辅助（90%→60% 随复杂度递减）
  • 布局受组件库限制
  • 安全天生保障（无 HTML）
  • 适合：重视安全性

混合建议

LLM 输出 JSON DSL（必须含 type）
  │
  ├─ type 是预定义组件 (table/card/row/tabs) → WASM/JS 映射到安全 HTML → iframe 渲染
  │
  └─ type === 'raw_html' → 走 DOMPurify 严格消毒 → iframe sandbox 渲染
                             ↑ 逃生舱：LLM 需要自由布局时
                               但必须经过最严格的安全检查

既能享受 DSL 的组件化安全，又保留 HTML 的灵活性。

LLM 大部分场景用 DSL 组件，少数需要自由布局时用 raw_html 逃生舱。

最终推荐

Phase 1: JSON DSL + 组件库（JS 渲染），走通交互协议
Phase 2: WASM 作为 DSL→HTML 安全映射层
逃生舱: raw_html 类型 + DOMPurify 高强度消毒
