WASM + HTML 头脑风暴

探索 WASM 在 Agent 富内容交互中的角色和可能性

场景：WASM 作为交互层

方案 A：WASM 安全网关

可行 推荐探索

LLM → HTML → WASM 安全网关 → 安全 HTML → iframe render
                            ↓
                     解析 DOM，移除危险属性
                     重写 data-action 绑定
                     注入白名单校验
                     输出纯净 HTML + 交互契约

WASM 在这里类似 DOMPurify 但更彻底：
- 编译期保证：输入输出类型严格，无 JS 逃逸路径
- 确定性：相同 HTML 永远产出相同安全结果
- DOM 解析在 WASM 内完成，不依赖浏览器 DOM parser
- 缺陷：WASM 解析 HTML 需要自带 parser（复杂度高）

方案 B：WASM 全栈渲染（HTML+Canvas）

高复杂度

LLM → HTML → WASM 渲染器 → Canvas 输出
                            ↓
                     WASM 管理热区
                     点击热区 → postMessage
                     不涉及 DOM

优势：完全无 DOM 注入风险，像素级控制
代价：
- 需要实现 HTML→Canvas 的布局引擎（工作量巨大）
- 文本渲染、换行、可访问性全部自建
- 交互热区需 WASM 维护 → 增加复杂度
- 不适合初期版本

方案 C：WASM DSL 渲染器

高复杂度 中长期

LLM → JSON DSL → WASM 渲染器 → Canvas
                  ↑            ↑
             安全、结构化      像素级渲染
             无注入风险        高性能

结合 DSL 思路：

  • LLM 生成结构化 DSL（不是 HTML）
  • WASM 渲染器解析 DSL，直接绘制到 Canvas
  • 交互模型由 DSL 语义定义，不是从 HTML 提取
  • 最安全方案，没有 HTML 注入路径

方案 D：Hybrid — WASM 消毒 + DOM 渲染

可行 推荐

LLM → JSON DSL → WASM 安全层 → 安全的 HTML → iframe DOM 渲染
                  ↑               ↑
             DSL 结构校验     生成受控 HTML
             替换为安全组件

流程：

  1. LLM 输出 JSON DSL（非 HTML），如：
    {"layout":"row","children":[{"type":"card","title":"A","action":"select:a"},...]}
  2. WASM 模块将 DSL 映射到预定义的 HTML 组件库
  3. HTML 组件库是硬编码在 WASM 中的，不可被 LLM 修改
  4. 输出安全 HTML → iframe srcdoc 渲染

关键特性：
- LLM 不能输出任意 HTML，只能选择现有组件模板
- WASM 的组件映射表在编译期固定，无注入可能
- 组件库可扩展（注册新组件 → 重新编译 WASM）
- DOM 渲染保留可访问性

四个方案对比

方案 安全性 丰富度 复杂度 可行性
A: WASM 安全网关 高 高（任意 HTML） 中 ✅ 初期可用
B: WASM Canvas 极高 高（像素控制） 极高 ❌ 远程
C: WASM DSL 渲染 极高 中（受 DSL 限制） 高 ⏳ 中长期
D: WASM DSL→HTML 极高 高（组件库扩展） 中 ✅ 初期可用

推荐路线

Phase 1 (现在):   JS DSL → JS 渲染器
                    { DSL 校验, 组件映射, iframe 渲染 }
                    无 WASM，走通协议

Phase 2 (近期):    JS DSL → WASM 安全层 → iframe 渲染
                    加入 WASM 作为 DSL→HTML 的编译期安全保障
                    WASM 确定性地将 DSL 映射为安全 HTML

Phase 3 (远期):    JS DSL → WASM 渲染器 → Canvas
                    可选替换渲染后端，协议不变
                    WASM 直接绘制，跳过 HTML/iframe 中间层

结论

WASM 的价值不在替换 HTML，而在为 DSL→HTML 映射提供编译期安全保障。 初期先用 JS 跑通协议，后期 WASM 作为安全层渐進替代。
